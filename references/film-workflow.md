# Scoring a toon-explainer film

Tested end to end on 2026-10-22 with shots k01-k18 of "The Man Who Poisoned the World Twice" (89 s): new
narration, re-timed picture, 5 music cues, 12 effects, an ambience bed and one punchline dip, about $0.45 in total.
Paths below use `$SKILL` for this skill, `$TOON` for toon-explainer and `$FILM` for the film folder. Work on a copy of
the spec when you only experiment; never edit the user's originals without being asked.

## 0. Layout

```
$FILM/
  script.md            storyboard (Shot N / Voiceover / On screen) - toon-explainer input
  v3/spec.json         the film; shot ids k01..kNN, each with dur and vo
  audio/               everything this skill writes
    narration.json     tagged beats          vo.mp3, vo.words.json, vo.srt
    timeline.json/.md  events for scoring    soundtrack.json, assets/
    mix/final.wav      + final.wav.stems/, final.wav.manifest.json
```

## 1. Narration from the spec

```bash
python3 $SKILL/scripts/timeline.py beats $FILM/v3/spec.json --out $FILM/audio/narration.json
```

One beat per shot with the shot's `vo`. Now direct it: choose a `mode` per beat (serious cold open, `ironic` base,
`deadpan` for punchlines, `dramatic` for questions and reveals), add `[pause]` before a punchline, `<stress>` on the
key word, a `direction` only where the intent turns. Keep the words. Example: [film-narration.json](../examples/film-narration.json).

```bash
python3 $SKILL/scripts/speak.py --plan $FILM/audio/narration.json --out $FILM/audio/vo.mp3
python3 $SKILL/scripts/transcribe.py $FILM/audio/vo.mp3 --out $FILM/audio/vo.words.json --script $FILM/audio/narration.json
```

A 1200-character scene renders in one request (about 12 s); a full film in 3-5 requests joined into one MP3.
Check `script_match` (0.98+ is normal: numbers and "Jr." come back as digits/abbreviations) and listen to any
difference that is a real word change.

## 2. Re-time the picture to the voice (toon-explainer)

The new read never has the old timing. Picture follows voice:

```bash
cd $TOON
python3 scripts/script2spec.py $FILM/script.md --srt $FILM/audio/vo.srt --merge $FILM/v3/spec.json
python3 scripts/lipsync.py $FILM/audio/vo.mp3 --out $FILM/v3/vo.lips.json
uv run --with playwright python scripts/render.py $FILM/v3/spec.json --out $FILM/v3/picture.mp4 --workers 6
```

`--merge` rewrites every shot `dur`. Re-check shots that got shorter: in the test, k04 shrank from 8.0 to 6.7 s and
its 4.2 s counter no longer finished. If the film's spec is generated by build scripts (`build/merge_film.py`), merge
there or the next rebuild undoes it. Render a `--scale 0.5` preview while iterating on sound; mux the final mix onto
the full-resolution render at the end.

## 3. Read the timeline

```bash
python3 $SKILL/scripts/timeline.py events $FILM/v3/spec.json --words $FILM/audio/vo.words.json \
  --script $FILM/script.md --out $FILM/audio/timeline.json --md $FILM/audio/timeline.md --tiers AB
```

`timeline.md` lists each shot with absolute start/end, background, grade, when speech runs, and its events with a
tier and a suggested library sound. With `--script` it also shows the director's sound plan written in the
storyboard: a `Music map:` block above the first shot (moods per act, where the music stops) and a `- Sound:` line per
shot (`SOUND PLAN: heavy metal knock on "knock"`). Treat that plan as the brief: realise it with real anchors, and
add tier-A events it forgot. toon-explainer's `script2spec.py` ignores both, so they are safe in `script.md`. `*` marks background/grade changes: candidate music sections. The tail lists
speech pauses of 0.6 s or more: slots for stingers and music stops. A full 8.7-minute film produced about 590 events;
only tier A and the B events that carry a joke deserve sound.

## 4. Write soundtrack.json

Plan the music first, then effects:

1. Split the film into sections at `*` shots where the mood really changes (cold open, setting, act turn, sincere
   passage, ending). Long films land around 3 changes a minute; a sustained scene can hold one cue longer.
2. Cover the moods as cheaply as possible: library themes first (`{"music_library": NAME}`, see
   [music-library.json](music-library.json)); then one Lyria Pro track per act holding the remaining moods as timed
   sections, declared in `"sections"` and picked per cue with `"section"`. A mood that returns reuses its section.
   The demo cold open used one 100 s Pro track with five sections ($0.086 with its speech check) instead of four
   separate tracks ($0.20).
3. End cues on the cut (`"end": "k06"`, `fade_out` 0.04 for a hard stop) and put a `dip` over each dry punchline.
4. Effects: tier-A events, then the B events the narration points at. Aim for 4-7 a minute in long films. Prefer
   `{"library": "..."}` assets (cached, shared); write a custom `sfx` prompt for anything specific.
5. Ambience only where it sells a place (a press room, a factory, a street), under the music, ending on the cut.

Field reference and anchors: [soundtrack-plan.md](soundtrack-plan.md). Example: [soundtrack-plan.json](../examples/soundtrack-plan.json).

## 5. Build

```bash
python3 $SKILL/scripts/soundtrack.py --plan $FILM/audio/soundtrack.json --dry-run       # cue sheet + cost
python3 $SKILL/scripts/soundtrack.py --plan $FILM/audio/soundtrack.json --assets-only   # generate, 4 in parallel
python3 $SKILL/scripts/soundtrack.py --plan $FILM/audio/soundtrack.json \
  --out $FILM/audio/mix/final.wav --video $FILM/v3/picture.mp4 --video-out "$FILM/v3/$TITLE (scored).mp4"
```

The build takes seconds per minute of film. It prints the resolved cue sheet, warnings (a music cue shorter than its
span, an effect outside the film) and QA. Re-running after a plan edit reuses every asset; only changed prompts pay.

## 6. Check and iterate

QA (automatic, `long` targets): -14 LUFS +/-1, peak below -0.8 dBFS, music 14-26 dB under the voice while words are
spoken, effects not covering words for 0.25 s or more, no unintended silence of 2 s or more, 3-9 effects a minute.
`bed_depth_db` is informational: dense narration lowers it without the music being louder.

Then, optionally:

```bash
python3 $SKILL/scripts/review.py "$FILM/v3/$TITLE (scored).mp4" --out $FILM/audio/review.json \
  --context "Cold open about a 1924 press stunt; turns comic in 1921 Dayton."
```

Verify each issue in the stems before changing anything: in testing, a review told what a moment should do reported
it as missing although the stems showed it was there. Fix by editing single cues (`gain_db`, `at`, a new dip) and
rebuild into a new `--out`.

## Pitfalls seen in testing

- An effect source can start with up to 0.45 s of silence; `generate_asset.py` cuts from the attack so the hit lands on
  its anchor. If a custom `file` asset has leading silence, trim it or use `source_start`.
- A Lyria request can fail mid-stream. Partial bytes are kept as `.rejected`; the error names the asset. Delete that asset's
  `.manifest.json` and run `--assets-only` again to pay for a new attempt.
- Lyria Pro moved section boundaries up to 3 s from the prompt; `soundtrack.py` snaps each to the measured change and
  warns when a change is faint or a cue runs into the next section.
- One Pro track came back with mumbled pseudo-speech under a "dark" section (STT heard "dragons off the dining
  cars"). Its prompt said "documentary" and the old suffix mentioned a narrator. Music is now checked for speech
  automatically; regenerate a flagged track or keep cues out of the flagged span.
- ffmpeg 9 drifts timestamp-based trims after `adelay`; the mixer pads and cuts by sample count. Keep it that way.
